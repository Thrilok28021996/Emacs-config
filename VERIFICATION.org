* The twelve criteria

** 1. Create a new project through a template

Proven by =stage1-check.el=: =my/new-project= creates
=projects/<slug>.org=, the file carries the =#+TODO:= line, a kanban
block, a =Tasks= heading and a file-level ID.

#+begin_example
PASS  my/new-project creates projects/<slug>.org
PASS  created file carries the #+TODO line
PASS  created file carries a kanban block
PASS  created file has its Tasks heading
PASS  my/new-project refuses to overwrite
#+end_example

** 2. Create a new learning subject through a template

Proven by =stage1-check.el=, same code path but asserted separately:
=my/new-learning-subject= writes =learning/<slug>.org= with the mirrored
workflow line and a board, and the agenda discovers it.

** 3. Every project and learning document has its own board**

Proven by =stage2-check.el=: the fixture project file renders a board with the
seven active states in workflow order, each task in its own state column, and
=CANCELLED= absent while still present as a heading.

** 4. The consolidated board shows tasks from all files**

Proven by =stage2-check.el=: the board in =dashboards/projects.org= is scoped to
the two directories and contains both a project task and a learning task.

** 5. Moving a task on the consolidated board updates its original file**

Proven by =stage2-check.el=, and this is where the one serious bug was found:
org-kanban resolved a row to a *neighbouring heading* because it searched the
target buffer from wherever point happened to be. The fixture caught a move that
changed the wrong task. =lisp/my-kanban.el= replaces the resolver and refuses to
guess when a heading cannot be found.

#+begin_example
PASS  moving a row on the consolidated board updates the project file
PASS  the move left every other task in its own state
PASS  after the move the task shows in the NEXT column
#+end_example

** 6. The agenda shows tasks and deadlines across projects and subjects

Proven by =stage1-check.el= (directory-based discovery, so a new file needs no
config edit), =stage4-check.el= (all three agenda dashboards build; the project
view shows project tasks only, the learning view learning tasks only; a due
deadline is displayed) and =stage6-check.el= (agenda build over 40 fixture
projects, 0.56 s).

** 7. Org-roam resolves backlinks between zettels**

Proven by =stage3-check.el=: an =id:= link between two hand-written zettels is
indexed with both endpoints, the target gets a backlink, and the link resolves
to the target's file. The same stage proves the projects tree is not part of
the index.

** 8. Zettels can be linked without duplicating content**

Structural, not merely asserted: a file-level ID per zettel, written by
=C-c k e= after the file is created by hand, links by =id:=, and the design rule
that a project or learning file links to a zettel instead of restating it.
=stage3-check.el= proves the link and backlink machinery; =C-c k v= shows what
links to the note at point.

** 9. Flashcards can be created and reviewed — NOT IMPLEMENTED**

=org-fc= is not on MELPA, GNU ELPA or NonGNU ELPA (checked against all three
=archive-contents= files), so it could not be installed under the agreed rule of
MELPA + GNU ELPA only. It was deferred by decision, not attempted and failed.
No flashcard functionality exists in this system.

** 10. Research annotations connected to knowledge notes — NOT IMPLEMENTED**

Two independent blockers, both verified:

- A terminal cannot display images, and =doc-view= renders pages as images. No
  pdf-tools means no text layer either.
- =nov.el= has **no annotation feature at all** — no highlight store, no
  annotation list. There is nothing to attach an annotation to.

What exists instead: EPUB renders as text, the source file is attached to its
note, and notes are written in Org and linked. See =ORG-PKM.org= → Reading.

** 11. Git preserves the authoritative Org files and attachments**

Proven by =stage6-check.el=: =bin/backup.sh= commits pending work in both
repositories and archives each; the knowledge archive is extracted into a
temporary directory and **every tracked file is compared byte for byte**. The
script is run against copies of both trees, because it commits and a test must
never commit to the repository it is testing. The ignore rules of both
repositories are checked from both directions: =.DS_Store= is ignored,
zettels, the inbox, attachments and templates are not.

** 12. Rebuilding the Org-roam database does not destroy knowledge**

Proven by =stage3-check.el=: the database is deleted, rebuilt, and the node
count, the link count and the md5 of every zettel are compared before
and after.

* Documentation is gated too

Four documents, four jobs:

| File | Job | Verified by |
|---|---|---|
| =cheatsheet.org= | key reference | every live binding must appear; every taught key must resolve |
| =tutorial.org= | guided course | every taught key must resolve; must cover the knowledge layer |
| =HANDBOOK.org= | the built-in subsystems (dired, calc, eshell, macros, …) | every key must resolve or appear in the inventory; every =M-x= command must exist |
| =INVENTORY.org= | every binding in every reachable keymap, generated | row count, block presence, and the key coverage check |

The inventory currently holds **4,304 bindings across 32 keymaps**. For scale:
this Emacs ships **5,135 interactive commands** and MELPA carries **6,351
packages**. The inventory documents what is *bound*; the rest is reachable only
through =M-x= and is not claimed here. That is the honest boundary of "leave
nothing unturned": a complete list of everything Emacs can do is the manual.


=stage7-check.el= keeps the documentation honest, because a document
that teaches a key which does not exist is worse than no document:

- every =C-c= binding in the live keymaps must appear in =cheatsheet.org=, and
  the master table there is generated from the keymaps, not typed
- every key the cheatsheet and tutorial teach must resolve to a command, checked
  in an Org buffer so =C-c C-c=, =C-c C-t= and friends are found in =org-mode-map=
- neither document keeps a section describing removed software, and the
  cheatsheet may not name a package that is not loaded
- both documents must cover the knowledge layer (creation, dashboards, blocks,
  attachments, backlinks, kanban, org-ql, EPUB, backup, gates)
- both must point at =ORG-PKM.org= and =VERIFICATION.org= instead of duplicating
  them

It immediately caught a real error: the tutorials taught =C-c C-x C-w= to move a
kanban row, and that key is =org-cut-special=. org-kanban ships *no* keybinding
at all — =org-kanban/shift= is only reachable through =M-x= — so =C-c k m= was
added and is now tested through the transient map with real keystrokes.

* Known limits

- Seven-column kanban boards render at 305–324 characters per line. They do not
  fit a terminal. The one-line fix is documented: =:range (TODO . REVIEW)= on
  the block.
- An empty tree renders an empty board, because org-kanban derives columns from
  the files it scans.
- =org-super-agenda= grouping applies to the three dashboards only.
- PDF reading happens outside Emacs.
- The Org layer costs ~20 ms of startup time over the bare coding config.
