#+TITLE: Org setup and key layout
#+STARTUP: overview

This file explains what is left of the Org layer and why. For the key list,
see =cheatsheet.org=; for the checks, see =VERIFICATION.org=.

* The data

=~/knowledge= is a Luhmann-style zettelkasten: numbered notes, linked by =id:=
links, with =main-box=, =literature-box= and a hand-curated index. Files are
created and numbered by hand. Nothing in Emacs picks the next number.

The Org-roam index lives in =~/.emacs.d/org-roam.db=, outside the data tree. It
is a cache: delete it and =C-c k s= rebuilds it from the Org files.

* Loaded modules

| File | Job |
|------+-----|
| =init.el= | Global keys, editing, Eglot, Flymake, Magit, projects, theme |
| =lisp/my-org-pkm.el= | =my/knowledge-dir=, shared Org settings, eight workflow states |
| =lisp/my-roam.el= | Index, node find, backlinks, graph, sync |
| =lisp/my-reading.el= | Route =.epub= files to nov-mode |
| =lisp/my-help.el= | Open this document |

Only these modules load. The modules for project files, capture, boards,
dashboards and the reading queue were removed with the old tree layout. Their
bindings and checks went with them.

* Why the prefixes look like this

- =C-c k= is the zettelkasten and nothing else: find (=f=), backlinks (=v=),
  sync (=s=), graph (=g=), this document (=H=).
- =C-c o= holds Org clocking (=I=, =O=, =R=) and link insertion (=i=).
- =C-c c= is code, =C-c e= is diagnostics, =C-c g= is Git, =C-c p= is projects,
  =C-c v= is Conda, =C-c w= is windows, =C-c i= is indentation, =C-c f= is
  recent files, =C-c s= is imenu and =C-c t= is the theme.

Redundant aliases went away. =C-x b=, =C-s= and the built-in undo keys already
do what the old three-letter aliases did. The line-moving keys also went: Org
owns the same chord and the binding behaved differently depending on the mode.

* Workflow states

Files that carry a task list use the same eight states in board order:

#+begin_src org
#+TODO: BACKLOG(b) TODO(t) NEXT(n) DOING(o) WAITING(w) REVIEW(r) | DONE(d) CANCELLED(c)
#+end_src

The state sequence is still checked by =stage1-check.el=. There is no board
renderer in this configuration now.

* What to expect when something is missing

- No key creates a project or captures a task. Do that in the Org file by hand.
- No dashboard refreshes. The files under =~/projects= are data, not config.
- Eglot bindings are present but Python has no language server installed here.
- =C-h k= plus a key remains the authoritative answer for what is bound.

* Verification

=emacs-sync.sh verify= loads the config and runs the checks. The gates check
the workflow and the exact key contract, the Org-roam index in a temporary
tree, EPUB routing, and the docs against the live keymaps.
